KUI / KUID protocol

Binary event/response protocol between the desktop window manager (KUID) and Aqua clients such as doom-aqua.

Identity: magic 0x3149554b (“KUI1”), version 9. Events travel on client stdin; responses travel on client stdout (or a duplicated protocol fd).

The wire format is native packed C structures, so both endpoints must agree on field sizes, order, alignment, and version.

Display command stream

Each packed command begins with uint16 type, uint16 size, four signed coordinates, foreground/background colors, and flags. Command-specific bytes follow.

Doom Aqua example

  1. KUID sends INIT for a 640×400 client area.
  2. Doom replies with loading display, title, constraints, and a 5-second timer.
  3. After WAD initialization, KUID sends TIMER.
  4. Doom renders 320×200, producing a roughly 262 KB command stream, then requests a 28 ms timer.
  5. KUID replays the stream, composites the window, and presents the framebuffer.

A large display stream can block the client response write while KUID is replaying/presenting it. Partial damage and cached surfaces reduce this backpressure.
