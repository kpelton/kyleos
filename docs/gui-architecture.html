KyleOS GUI Architecture

This document describes the desktop compositor, KUI protocol, application lifecycle, rendering pipeline, input handling, and Save As flow.

Application lifecycle

User clicks icon/menu
Shell forks and execs the application
Shell sends KUI_EVENT_INIT
App returns title, constraints, and display commands
User generates pointer/key/timer input
Shell forwards a serial-numbered event
App responds with commands and actions
Shell replays and composites the window
User closes the window
Shell sends close, closes pipes, and reaps the child

Rendering pipeline

input → shell → kui_event → app event loop
                         ↓
                    kui_surface
                         ↓
             serialized display commands
                         ↓
              shell validates and replays
                         ↓
       windows + menus + taskbar + cursor → frame

The display-command limit is KUI_PROTOCOL_MAX_DISPLAY (512 KiB).

Input and scrolling

→

→
App event loop
→
Shared scrollbar state
→
Visible rows / columns

Wheel movement is normalized by kui_scrollbar_wheel(). Arrow buttons share the same state and repeat timer.

Save As flow

App opens shared Save dialog
Dialog presents directory and filename field
User types filename and presses Enter
Dialog checks whether target exists
If existing: overwrite confirmation
Dialog returns selected absolute path
App writes the file
App returns KUI_ACTION_FILE_SAVED

Path updates use bounded overlap-safe copies. Shell lifecycle diagnostics are written to /SHELL.LOG; stdout remains reserved for KUI protocol traffic.
